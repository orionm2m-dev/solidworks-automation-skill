# Explicit island sketch component

This staged component compiles exactly four serialized annular-strip footprints into four native sketch specifications. It reuses `sw_cam_signed_mixed_profile` and `sw_cam_signed_mixed_profile_sketch`; it does not add a CAM endpoint, create a CAM feature, call AddIsland, generate operations or paths, save, retry, or adopt uncertain sketches.

`compile_loops(loops, *, plane_z_mm, sketch_names, plane_names)` requires four distinct declared angles and four separate names. Every footprint has exactly two opposite-direction, concentric minor arcs and two lines. Endpoints and their serialized Z are preserved. Midpoints are computed analytically and passed through the existing bounded self-intersection/closure validator. No contour offset, scaling, polygon substitution, or automatic plane relocation is performed.

`create_one(sw, *, process_id, document_path, source_sha256, expected_needs_save, spec, check, claim, persist, report)` uses the unchanged signed native sketch builder. The enclosing reviewed action must own the exact process lifetime and document, immutable source/evidence pins, runtime and event health, before/after full CAM invariants, operation lock, and durable target/action replay marker. `claim()` consumes the action before any sketch mutation. `check()` runs around the reused native calls. A fresh per-sketch report retains partial outcomes; failure stops without deletion or retry. The component verifies exact CAD tree additions, old planes and solid-body invariants, source identity, sketch closure and model-coordinate native readback. It accepts the explicit expected dirty flag so a caller may create subsequent sketches in one deliberate transaction without an intermediate Save.

`verify_readback(spec, observed)` uses the existing native endpoint/midpoint/radius/independent-length matcher. Native arc direction and oriented normal must have been read by the signed reader. It does not use the underlying untrimmed curve interval. Reversed native entity order is accepted only through the exact unambiguous geometric mapping.

The current compile-only input uses the pinned full-side footprints projected at Z25.8. This is a construction plane, not the actual guide top Z25.5, not the straight-side upper limit Z25.0, and not an approved AddIsland start height. The definition plane and island start/depth semantics remain for root's explicit-feature integration review. The compiler deliberately rejects moving these serialized loops to another plane. The guide proof covers the straight side band; it does not certify the complete rounded-corner projection.

Prepared evidence: 25 focused software cases plus one final receipt-failure case; the actual pinned four-loop contract compiles to sixteen segments without touching an application. The tests exercise the real segment writer and native row matcher with typed values; CAD scaffold orchestration is simulated. No native creation of these new sketches has been performed. No machining or island-association qualification follows from this package.

Integration is intentionally separate: use a reviewed isolated R25 working branch and preserve the rejected saved roughing evidence. Do not pass the new sketches into historical single-feature or fixed-operation contexts by relabeling receipts. After this component is reviewed, the enclosing action can create the sketches in order and bind their exact observed names/geometry to a separately reviewed feature/AddIsland action.

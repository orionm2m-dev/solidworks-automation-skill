# Current saved circular-pocket continuation

Status: staged and tested offline; no native qualification is claimed.

The existing `solidworks_cam_configure_guide_definitions` endpoint accepts an explicit `configuration_mode="current_saved_circular"`. It requires the actual completed `MILL_CURRENT_SAVED_CIRCULAR_POCKET_V1` creation receipt, current PID/lifetime/path/source SHA, the exact new feature ID and its single Rough operation ID, the existing candidate tool and all observed consumer IDs, and a pinned field recipe. It does not substitute a circular pocket for the old compound-hole authority. The original mode and old two-operation capture contract remain unchanged.

The loader verifies the original configuration authority, the sketch/feature/operation/Save action chain, paired complete captures, actual geometry delta, the full retained route, the protected reference feature and operation-owned parameter/NC observations. Prepare is read-only. Apply keeps the existing durable once marker, full SetTool barrier, immediate own-field readbacks, two final full captures, and optional strict-int-zero Save with two exact saved captures. Partial outcomes retain actual returns and block replay.

For a particular floor recipe the caller may explicitly declare `dependent_readbacks=[{"operation_native_id": <new rough ID>, "member":"DepthAllow", "expected":1.0, "new":0.0}]`. Admission requires the current own DepthAllow and the same operation's declared floor_allowance expected/new to match exactly. Only that fixed dependent observation is allowed; every other captured field remains protected. An empty list retains the strict default. This is an expected observable delta for this request, not a universal API alias claim and not a change to the old compound mode.

The existing sealed `solidworks_cam_generate_configured_local_group` endpoint accepts `generation_mode="current_saved_circular"` only after the matching completed configuration Save. The existing one-shot sequence exports pre-CL, generates only the configured new Rough, requires a positive actual path, saves once, and compares post-CL with all previous complete CL blocks. Unknown returns, missing paths, dirty/geometry/tool/NC drift, runtime drift and events stop the sequence without retry.

The reusable circular context retains the original reference capture and separately reads the actual new pocket. Sketch dirty is a strict Boolean observation; its file hash changes only through verified Save. New targets become valid generated observations only after their explicit GTP attempt and a positive bounded count. The internal circular read ceiling is fixed at 48000 to cover the fuller capture sequence; old contexts retain 24000 and no request can set this ceiling.

No toolholder clearance, physical cutting conditions, full hidden CAM geometry, universal CL/world frame, production acceptance or reopen persistence is established by this workflow. Actual CL geometry must still be reviewed after successful generation. All current tests are synthetic/file-only; actual historical6cba evidence is used only to check the existing pure authority shape.

Circular continuations use the same narrowly scoped SW mass comparison as creation: finite `sketch_state.solids[*].mass_raw` entries may differ only within the existing relative `1e-10`, absolute `0` body tolerance, with identical body/array counts and exact bounds. Comparison copies are aligned; raw captures and their digests remain intact. Every CAM, tool, geometry, source and other state field keeps its existing exact rule. Generic configuration and generation paths remain exact.

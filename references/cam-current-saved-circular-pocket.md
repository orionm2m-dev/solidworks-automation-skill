# Current saved circular pocket and one Rough definition

The existing `solidworks_cam_add_circular_pocket_plan` endpoint accepts the explicit `mode="current_saved"` pilot. Its original mode is unchanged. This branch uses a genuine completed current parameter configuration as the protected baseline. It does not manufacture a compound-feature authority for the new pocket.

`prepare` reads twice and validates the exact process lifetime, add-in, saved path/hash, reference feature/setup, operation order, observed parameters and existing tool consumers. It exposes the requested Rough catalogue entry and default tool type/diameter/protrusion expectation. The new feature's actual catalogue can only be inspected after creation; it must contain that exact entry before insertion.

`apply` consumes the immutable prepare and one exclusive marker. It creates one named XY circular sketch, calls the declared `ICWSetup.CreateMillFeature2` once for a closed pocket, inserts one explicitly selected Rough operation, and performs checked CAM Save. There is no GOP, GTP, automatic retry or rollback. Every attempted/returned action and partial capture is durable before the next step. A partial result requires an explicit separately reviewed continuation.

The owner setup axis is explicitly pinned to +Z or -Z. Reverse direction is fixed false: primary end-condition documentation defines the selected sketch as the top and depth along the Mill Part Setup direction. The sketch normal alone does not establish this direction. Before inserting the operation, actual sketch world/local transform, circle radius/centre, native feature axis/start/depth, ownership, both contour chains and zero islands are checked. Separated contours require positive signed depth along the setup axis. Coplanar chains are retained as a known representation; the nominal end is then interpreted from header axis/depth, not measured from separated planes. Physical depth, a general CL frame and manufacturing acceptance remain unqualified.

The new operation must be an unsuppressed, ungenerated Rough linked only to the returned feature in the selected operation setup. Its own tool ID is read, never predicted. The requested default tool type and dimensions must match. An existing crib tool may be reused or exactly one observed entry may be appended; every old crib entry and observed tool/NC witness is retained. Configuration of the tool and parameters is a separate explicit continuation. Geometric machining allowance already represented by the requested pocket must not be added a second time without engineering review.

The completed receipt scope is `MILL_CURRENT_SAVED_CIRCULAR_POCKET_V1`. It includes the original authority pin, canonical request binding, actual new feature/operation IDs, created sketch names, four action outcomes, paired snapshots after each stage, and paired saved snapshots. Default scalar readers still require the legacy Rough/Finish pair; the circular path opts into exactly one Rough. Explicit continuation loaders must validate this new scope and its complete action/delta/Save chain.

Preservation covers captured IDs/order/links/suppression/path counts, observed tool and NC scalars, reference profile and SW body bounds/mass. It does not prove every hidden CAM geometry field or full BRep identity. Saved source changes are accepted only after exact successful Save and unchanged captured state. CAM changes may occur while the host dirty flag is false. Metadata compatibility is checked before mutation, including the factory, island getter and reused NC interfaces.

Offline tests cover the actual Pydantic wrapper, declared local metadata, composition of existing own-tool/NC readers, strict geometry and full-state deltas, partial failures, event/runtime stops, Save and no replay. Native creation in this mode remains a qualification step.

Circular snapshot comparisons preserve the original `sketch_state.solids[*].mass_raw` arrays and their receipt digests. Only comparison copies may align finite DOUBLE mass entries after the existing SW body comparison accepts relative tolerance `1e-10`, absolute tolerance `0`. Body count, mass-array length, exact finite six-value bounds and every field outside these mass arrays remain strict. Invalid/nonfinite values and booleans are rejected. The same circular-only comparison applies to paired prepare/stage/Save captures and explicit configuration/GTP/CL continuations. Generic modes retain exact comparison. This accounts for observed numerical variation in repeated mass-property reads; it does not qualify physical geometry.

The radius guard uses the measured sketch circle and the declared native CIRCLE/complete-circle readback, together with exact owner axis, start and GetDepth. `GetBoundParams` returns three observed values whose radial interpretation is not documented as an exact analytic diameter. Those finite raw values are retained and protected between captures; they are not substituted for the circle radius. Coplanar top/bottom circles still do not establish measured physical bottom depth.

The explicit `continuation_mode="after_feature"` handles only the recorded historical boundary where sketch and feature creation returned, the sketch was verified, and the old diameter-from-bounds guard stopped before any operation insertion or Save. It pins the immutable partial receipt, consumed old marker, actual original apply request and successful original prepare. All original operations, geometry and source must be preserved. This is a precise continuation, not automatic recovery of arbitrary partial failures.

Direct `action="apply"` consumes the exact original prepare path/hash; no additional native prepare round is required. The existing dirty-document admission is reused only with the exact verified historical document snapshot. Two fresh full captures must match the already-created feature, pass the analytic geometry and catalogue checks, and retain all old state before a new marker is claimed. Only one InsertOperation and checked Save follow, each with paired captures: six full captures in total. The report action is `resume_after_feature`, with two actual actions, explicit history pins and separately named raw historical snapshots. The old receipt and marker remain untouched. The completed-authority loader recognizes this explicit chain without pretending the original two creation calls were repeated. The normal four-action mode and its clean initial-state requirement are unchanged.

# Selective GOP from recovered and saved pocket authority

This pilot extends the existing `solidworks_cam_qualify_mill_feature_operation_plan` endpoint with `feature_kind="autodetected_pocket"`. It reuses the selected-feature RETAIN=1 lifecycle. Existing open-pocket and contour-qualified circular authorities retain their previous behavior; other tool schemas do not gain this new authority.

The new route requires four additional fields: `definition_recovery_receipt_path`, `definition_recovery_receipt_sha256`, `definition_save_receipt_path`, and `definition_save_receipt_sha256`. The recovery must be a completed `definition_only` result from [the read-only continuation](cam-autodetected-pocket-recovery.md). A separate existing `mill_qualification` Save must show strict native integer zero, complete readback, zero events/operations, one exact feature setup, a changed target-file hash and a clean document. Its before/after/final-state envelope is checked directly. Save does not establish persistence after reopening.

The original uncertain creator and consumed creation marker remain immutable. The recovery verifier supplies the exact observed Attribute suffix, selected header and inventory. Only the historical mutable target pin is replaced by the explicitly verified saved target pin; original CAD, geometry, raw receipts, marker and code/evidence pins stay protected. The caller supplies actual current process, path, source SHA and feature ID. No historical project ID is built into the tool.

Use `action="prepare"` to capture fresh current state and obtain `state_sha256`. Use `action="apply"` with that hash and a fresh JSON receipt. Prepare/apply require the clean saved definition and zero operations. Three bounded captures protect source, configuration, setup/feature identity, scalar header and analytic reference circle. The current feature tree must match the exact recovered tree; unseen Attribute rows are not ignored. Body comparison uses the existing tolerance, with actual observations retained in diagnostics.

Apply consumes a durable marker for this feature before one `ICWFeature.GenerateOpPlan(1)`. Success requires 1–32 unsuppressed new operations, actual operation setup/operation/tool IDs, raw operation/tool types, sole links to the selected feature, no generated paths and zero toolpath records. Source, feature, setup, sketch and other captured state remain protected. Only the ordinary dirty flag may change as a consequence of GOP. Events, partial reads or mismatches leave the consumed attempt unqualified; a new receipt filename does not authorize replay.

A successful response establishes draft operation definitions only. Four reported islands do not prove island contours, feature association, stock clearance or physical depth. Tool scalars do not prove a physical tool/holder or cutting recipe. No GTP, Save, stock setter, rebuild, UI input or automatic retry occurs. Numerical machining, production and persistence acceptance remain false. Software tests are separate from live qualification; no universal native success is claimed.

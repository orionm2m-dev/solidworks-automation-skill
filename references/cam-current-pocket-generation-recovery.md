# Recover an observed first pocket generation

`solidworks_cam_recover_generated_current_pocket` is a reviewed pilot continuation after one selected Rough GTP returned int0 and complete postcapture failed its protected-state comparison solely at one explicitly observed XYFeed scalar. No setter, tool assignment, GOP or GTP is called by this endpoint.

The request binds the exact owned process/lifetime, file/source SHA, feature and ordered Rough/Contour IDs, immutable uncertain generation receipt, exact observed before/after XYFeed values, and fresh receipt/CL paths. It reuses the original successful current tool context, recipe, actual seven field readbacks, consumed generation marker and all protected file pins. It recomputes the generation delta using a local comparison copy with only that one observed scalar changed; neither original receipt nor actual state is rewritten. The feed change cause and cutting conditions remain unqualified. No multiplier or flute-count rule is inferred.

There are five full fresh captures: current generated state; Save-before, which also serves as the second generated-state confirmation; Save-after; CL-before; CL-after. Both initial reads must exactly match the immutable observed generated pair. Existing identity/event/runtime guards and the native Save/CL primitives are reused in one session. A source hash change is accepted only after strict native Save int0; the raw return/new hash remain recorded even if a later read or export fails. A clean pre-Save CAD flag is only a bound observation, never proof that CAM was persisted.

A new source/target-specific durable marker permits at most one Save/export packet. Any uncertainty stops without replay. The earlier generation receipt remains uncertain and its false runtime flag remains historical evidence. Only current fresh guards can establish the new invocation's result.

On complete success, `current_context_verified` and `recovery_saved_context_verified` refer to the freshly saved context. Its payload scope is `CURRENT_GENERATED_POCKET_CONTEXT_V1`, explicitly rejected by the old GTP-false current-context loader. `GTP_attempted=false` truthfully describes this invocation; historical generation is linked separately. The output includes exact current saved inventory/parameters, source transition, native export SHA, sole operation/count binding and raw setup transform. CL-to-world mapping, guide sweep, stock entry, tool seating, units, feeds, production and reopen persistence are not qualified. A separate explicit generated-context consumer is required for subsequent mutation; no such consumer is introduced here.

Native recovery qualification is pending. Software tests cover exact authority, one-shot actions, five fresh captures, late failures retaining Save facts, schema bounds and exclusion of the old context loader.

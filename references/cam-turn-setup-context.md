# Existing TURN setup context

`solidworks_cam_inspect_turn_setup_context` reads the operation setup and its linked feature setup for an exact existing rough-bore or finish-bore operation (types 5/6). Supply the process ID and creation time, saved document path and SHA-256, operation index/type/native ID, linked feature IDs, and exact feature/setup/operation/generated-path counts including total record count. Optional expected feature-setup and operation-setup native IDs constrain a previously observed setup; omitted IDs are discovered in this bounded read. Only `action="read"` and `message_policy="vendor_default"` are accepted.

The existing operation reader supplies two complete captures under one event subscription, with process, document, file, selected operation and full inventory guards. The setup reader enumerates current feature and operation native IDs and reads `ICWBaseOpSetup.GetSetup()` to link the two independent setup collections. It never equates their indices. The repeated selected operation and its linked feature IDs must match the initial pinned operation before any frame getter. Canonical IUnknown equality is reported within each capture; native-ID equality with different canonical views is not a shared-storage or write-through claim.

For the selected setup pair, the reader preserves both raw Axis triples, `IsReverseDirection`, the operation origin from `GetSetupOriginInFCSSpace`, and the feature reference point from `IGetRefPoint`. The reference-point type metadata must identify the exact existing ICWPosition interface before its coordinate getter. Source units and a generic CL frame remain unqualified.

Both setup XY transforms are read. Their actual type metadata must identify ICWTransform before its exact GetData getter is called. GetData has six OUT values: four IDispatch objects, scale and a rotation flag. The reader records only the four objects' type GUIDs, type kinds and member counts, plus the raw finite scale and strict Boolean flag. It does not QueryInterface those four objects, read their coordinates or construct a matrix. This is an explicit type-discovery result, not a decoded frame. Standard IDispatch.GetTypeInfo(0) and ITypeInfo.GetTypeAttr calls use the same event checks as the CAM getters.

Missing setup IDs, unsupported metadata, invalid shapes, identity/count drift, a contradictory native link, any CAM event or incomplete cleanup stops the read without retry. A vendor that cannot provide native setup IDs may stop the first bounded read; the tool does not silently fall back. No CAM getters follow event disconnect. Partial evidence remains in the result.

No tool getter, feature profile, catalogue, setter, setup/operation insertion, toolpath generation, CL export or Save is performed. Existing operation readers retain their default behavior. This endpoint is offline tested; its first native setup read and actual transform output types remain to be verified. A successful read does not qualify reverse-setup creation, feature transfer, fixture access or machining.

A native read verified two equal captures of one feature setup and one linked operation setup, five features, eleven operations and six generated paths. Native IDs consistently linked the operation setup to its feature setup even though canonical COM identities differed. Raw feature and operation axis magnitudes differed (1 and 1000); they must not be interpreted as a unit conversion without further evidence. Both transforms returned four objects with the same observed type GUID; their coordinates were not read and no matrix convention was inferred. No CAM events or collected state changes were observed.

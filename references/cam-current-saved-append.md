# Current saved mode for one-feature MILL plan append

The existing `solidworks_cam_append_mill_operations` endpoint accepts an explicit `planning_mode="current_saved"` input in addition to its unchanged historical configured-plan input. The current mode supports `prepare` and `apply`; an explicit apply may save only after a verified additive delta. It cannot assign a strategy/tool, create a feature/setup, generate paths, simulate or write TechDB.

The current input inherits the exact PID/lifetime, clean saved part path/SHA, feature/feature-setup/operation-setup IDs, ordered old operations and native path counts of the current saved reader. It pins both the actual successful current-read request and result files. No absent identity fields are invented in the old result. Two fresh captures must match the pinned raw state and each other; prepare writes a new independently bound receipt.

Prepare exposes the feature's actual Attribute/GetAttribute, active attribute and both existing attribute catalogue getters. It also reuses the bounded `ICWMillFeature.IGetAllDefaultOperations(0/1)` and `GetTdbIdForDefaultOperation` reader. These return names/IDs, not pre-created operation parameter objects. A catalogue failure stops at that concrete getter; there is no guessed fallback or strategy assignment. The catalogue contents must be reviewed before considering apply.

Apply requires the immutable successful prepare, unchanged full captured state, and explicit matching actual strategy ID/name. The target must be unplanned in the observed empty operation setup. A document/source/feature keyed exclusive existing append marker is written before one `ICWFeature.GenerateOpPlan(1)` call. Exact local ABI is HRESULT with one IN LONG and no OUT parameters; a returned None is not Boolean failure. An internal wrapper runtime check runs immediately before claiming the marker and again immediately before dispatch. Failed/unknown calls never replay or roll back.

Two post-plan captures must agree. The existing delta validator ensures the old operation order/owners/links/captured own-tool scalars/path counts remain unchanged; new definitions must belong only to the selected feature/setup and have no paths. A distinct captured-only delta branch preserves the target header/profile, setup/member IDs and strategy/catalogues. It does not invent empty BRep bodies or claim full hidden holder/insert geometry, exact old CL coordinates, stock/fixture validity or machining acceptance.

Partial captures and returned step diagnostics are retained. Event, native, source, runtime or receipt errors revoke acceptance. Wrapper runtime verification is persisted before a prepare can authorize apply; post-call runtime drift preserves native evidence and updates only this call's receipt/marker. The historical configured-plan loader, its full-tool/body guards and its optional-save behavior remain unchanged.

Current-saved mode is staging-only until installed and read natively. Offline tests cover real synthetic traversal, prepare catalogues, HRESULT-only None return, once markers, bad deltas, event/exception stop, runtime drift before claim/dispatch and durable evidence. Successful tests do not prove that the actual selected strategy/defaults suit the part.

## Optional checked Save after append

`save_after_verified` is a strict Boolean, defaulting to `false`. Prepare requires `false` and never saves. Apply may explicitly set it to `true` while consuming a successful prepare made with `false`; the flag authorizes the later Save and does not change the prepared CAM binding or snapshot shape.

Save is attempted once only after both post-GOP captures agree and the additive delta is verified. Fresh process lifetime, document identity, original saved-source hash, immutable read pins, event state and runtime checks precede dispatch. The operation uses typed `ICWApp.SaveActiveDocument`, whose checked metadata is DISPID 12, HRESULT, zero arguments and no OUT parameters. The previously observed native binding returned strict Python integer zero. This branch retains that contract: Boolean, nonzero and `None` returns are recorded as uncertain and never trigger an automatic retry.

Only after a qualified return and quiet guards may the expected saved-file hash advance. Two new complete captures must agree and equal the verified pre-Save CAM state exactly, allowing only the document save flag to become false. All captured operation/tool data, profile steps, strategy, catalogues and path counts remain protected. The receipt records returned type/value, observed saved hash, dirty state, saved captures and verification flags. A partial Save or changed context retains available actual evidence, revokes success and keeps the no-replay marker. No error branch saves, generates paths, closes a document, rolls back or retries. Save readback does not prove reopen persistence or manufacturing suitability.

This optional extension has offline contract tests only until a separate native observation is recorded. The original prepare and default no-Save apply behavior remain unchanged.

## Selected definitions on a previously planned saved feature

`definition_mode="selected_insert"` is a separate bounded branch on this same endpoint. The default `retain_plan` branch still requires the real current-read request/result and an empty target operation setup. Selected mode does not call GenerateOpPlan and does not weaken that empty-setup guard.

Selected mode consumes `saved_authority_receipt_path/sha256`: an actual completed current-saved append/Save receipt with two equal clean saved captures and the exact resulting source hash. Prior process/lifetime/document/target ownership must match. Two new complete captures independently recheck the current saved file, operation order, path counts, target steps, strategy and catalogues against that saved baseline. No historical receipt is fabricated, and no missing historical identity field is inferred.

Prepare requires two explicit `insert_operations`, ordered Rough0 then Finish1, each with the actual catalogue name and ID. It also requires exactly two explicit `suppress_operation_native_ids`, equal to the final two old operation rows, and `anchor_operation_native_id` equal to the latter. Those rows must be the only operations linked to the selected feature, belong to its exact setup, be unsuppressed and have no generated paths or records. Prepare exposes this full selected instruction packet and performs no mutation.

Apply consumes the immutable successful prepare and uses one exclusive source/document/feature marker for the entire bounded batch. The fixed typed `ICWOperation.Suppressed=True` setter is DISPID 13, HRESULT with one IN VARIANT_BOOL and no OUT; Python assignment has no result value to interpret as HRESULT. Each returned setter is recorded, then two captures must prove exactly that one suppression flag changed (and optionally the document dirty flag). Every other captured operation, own-tool scalar, path count, feature/profile and setup value remains equal.

Insertion reuses the existing guarded `insert_selected_once` primitive. Exact `ICWMillFeature.InsertOperation` DISPID 44 accepts kind, default ID and an actual anchor IDispatch, returning a real operation pointer. The first anchor is the requested old operation; the second is the actual newly returned rough-operation ID. Each inserted operation must have the requested kind and ownership, readable own tool, and no paths. Own NC spindle/feed scalars are read without asserting physical units or cutting suitability. Two complete post-step captures protect all old rows (except the two explicitly authorized suppressions), and preserve profile/strategy/catalogues. A new shared-tool scalar change is an unexpected delta and stops the batch.

Before every native mutation, events, process lifetime, document/source/evidence pins and runtime identity are checked, including after the durable pending record. Returned evidence and partial/full captures survive later failures. Unknown results stop without a second setter, insertion, Save, retry or rollback. Optional checked Save reuses the same existing Save block only after all four steps have verified deltas. No GTP, tool assignment, strategy change or TechDB edit is allowed.

The selected-insert/suppression branch is an offline-tested pilot until its own native observation is recorded. It does not qualify machining, hidden full tool/holder geometry, CL-coordinate equality, stock or fixtures. The old RETAIN and Save behavior remain separately covered by regression tests.

## Read-only recovery and one remaining selected insertion

`definition_mode="selected_continue"` is an explicit narrow continuation, not a retry of selected insertion. It requires the immutable original partial receipt and its consumed attempt-marker path/SHA plus an explicit `retained_operation_native_id`. The original binding, saved authority and complete baseline remain pinned. Only the observed stop boundary is admitted: exactly two verified suppressions, then a returned rough-insertion pointer and actual ID, followed by the local unsupported-interface failure while resolving the own NC object. No pending/unknown mutation, later insertion, Save, event, runtime or receipt error may authorize this continuation.

This branch admits the exact unsaved CAM state with the unchanged original saved-file hash and process lifetime. The host document `needs_save` flag is observed as a strict Boolean and pinned across the fresh captures and subsequent apply; it may remain false after CAM definition changes and is not used as proof that CAM data was saved. Its `prepare` is read-only: two fresh full captures must prove all old captured fields equal except the two authorized suppression flags and exactly one appended rough definition with the recorded ID, kind, feature/setup, readable own tool and no path. Fresh own spindle-speed and XY-feed reads are mandatory and equal across both captures. The original failed result is not treated as completed operation readback. An invalid host save-flag type, a missing/extra/reordered definition, changed old path/tool/profile or unproven ID stop recovery.

The bridge declares `ICWNCParam2` IID `{7B7640FD-F53E-4B98-A073-EB4E6992E802}`. Before native mutation, every exact interface name used by the current capture/selected writer is admitted through the real bridge registry and generated IID check. Own-NC ABI checks cover `ICWMillOperation.IGetNCParam` DISPID7 returning IDispatch, `ICWNCParam.GetSpndlSpeed` DISPID7 returning DOUBLE, and `ICWNCParam2.XYFeed` DISPID23 propget returning DOUBLE. Their HRESULT/out-retval declarations are checked before a setter or Insert, so a local registry omission cannot first surface after insertion. Offline integration coverage runs the reused `read_own_nc` through the real bridge registry against primary generated metadata, including a negative missing-interface test before any setter.

Continuation apply requires its own immutable successful recovery prepare and a new exclusive continuation marker keyed to the old immutable outcome. It performs no suppression and never reinserts the retained rough operation. Exactly one finish definition is inserted after that actual rough ID. The retained own-NC scalars, all old captured rows, target profile, ownership and catalogue remain protected through the two post-insert captures and optional existing checked Save. `retained_operations` records the existing rough row; `new_operations` records only the newly inserted finish row. The original receipt/marker are read-only and never reset or overwritten.

Unknown continuation or Save results stop with preserved evidence and no replay/rollback. The old RETAIN empty-setup guard and checked Save block are unchanged. Successful offline recovery tests are not native proof or machining qualification; next native action is read-only recovery prepare.

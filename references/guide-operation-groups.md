# CAM 浅导向槽批处理（pilot）

本功能沿用已验证的原生 MILL 接口，限定为两个已绑定特征、每个特征一项粗加工和一项精加工。
它不是任意文档、任意特征的通用生成器。输入包含明确的进程、文档、配置和证据摘要。

## 创建定义

`solidworks_cam_insert_shallow_guide_definitions` 在一次受控会话中顺序插入四项定义。
默认工艺名称和 ID 必须来自当前原生目录；每次插入记录实际返回 ID，检查新定义的 NC
可读性，以及原有操作元数据和轨迹记录数。任何不确定结果立即停止，不自动重放。

该调用不设置刀具、不生成轨迹、不保存文档。成功仅表示四项定义存在于当前会话内存，
不表示其默认刀具、切削条件或几何轨迹已经合格。必须保存并另行验证持久化。

## 一次读取四项参数

`solidworks_cam_read_guide_parameters` 接受 `process_id`、`request_path`、`request_sha256`。
签封请求引用成功的四定义回执，并固定原文档及配置；不接受部分成功作为后续依据。

读取内容包括粗加工入口、切深和余量；精加工侧向/深度参数、引入引出和防过切选项；
NC、平面以及已分配刀具的尺寸。共享刀具只读取一次，随后复用同一读数。
读取前后比较原有操作，保持源文件字节不变，不调用 setter、GTP 或 Save。

完整的参数读取不等于制造单位、物理刀具、夹具、机床和切削条件已经合格。
原生返回的默认设置必须单独审查；不能把创建成功等同于可立即计算或投产。

## 失败和恢复

失败前没有原生写入时，保留原回执、核对零写入证据和源文件，修正代码后使用新输出。
已经尝试写入时禁止盲目重复。先根据实际返回 ID、状态和只读快照核实部分结果。
创建或读取的报告不代替独立保存与重新读取的持久化证据。

## 已验证范围

在 SOLIDWORKS/CAM 2026 的一个受控实例上，四项原生定义及其最小 NC 均读取成功；
四项完整参数读取也成功，并确认原九项操作元数据和六条既有轨迹记录数保持不变。
没有在本功能中比较 CL 字节、生成新轨迹或给出生产许可。

离线回归：定义及恢复边界 36 项，参数读取及 MCP 包装 32 项。
包含真实读取包构造链的离线测试；模拟测试和实际 CAD 验证明确区分。
其他 SOLIDWORKS 版本尚未验证。

## 配置四项定义并保存（pilot）

`solidworks_cam_configure_guide_definitions` 接受固定进程和摘要校验的请求文件。
请求必须引用成功的四定义回执、完整参数读数、现有合格刀具及显式参数配方。
只处理已绑定的四项 MILL 定义；不创建特征、不修改原有操作，也不生成轨迹。

先逐项指定刀具并读取实际结果，再设置配方字段。CAM 对当前目标自动更新的默认参数
和 NC 数值完整记录；其他目标参数必须保持不变。没有显式 NC 速度或进给 setter，
自动变化的切削条件仍是未合格的草案。粗加工支持入口、螺旋半径/螺距、切深、侧面与
底面余量、径向步距；精加工复用已有引入/引出、余量、切深、防过切及底面选项。

全部参数和受保护路线通过读取检查后，最多执行一次原生 Save，再读取文件摘要、
干净文档和全部四项参数。`model_saved` 仅记录已确认的 Save/文件事实；后续读取失败
仍返回不确定状态，不能再次盲目保存。`continuation_ready` 只在完整检查和事件清理
成功后为真。`saved_checkpoint_context` 保存新的文件摘要、文档/配置、拥有者、完整
保存后快照的引用和原始证据来源；旧回执保持原样。

完整快照只存储一次。动作记录保存索引、标签、选定操作 ID 和整个已保存快照的摘要；
保存前及最终完成前均重新校验引用。部分失败保留 pending/returned 状态，不自动重放。

当前新增配置调用的登记范围为离线配方、包装、真实构造/方法绑定和失败回归验证。
尚未登记这项组合配置与保存的原生成功，也未验证重新打开后的 CAM 持久化；
`persistence_after_reopen_verified` 保持 false。实际配置成功后仍需单独验证重新打开、
轨迹、夹持/刀具碰撞和加工条件，不能据此投产。

2026 年实际组合调用已确认四次刀具指定和三项完整参数配置；第四项部分字段完成后，客户端达到 1200 秒超时。未调用 Save 或 GTP。此部分结果不表示组合功能已成功完成；继续前必须核对原回执、进程退出及当前参数，禁止重放已确认的动作。

## 已确认前缀的继续配置（pilot）

`solidworks_cam_resume_guide_configuration` 使用两阶段请求：先完整读取当前参数并与中断日志核对，再继续从未尝试的字段。要求旧执行进程已经退出、没有待确认的写入、源文件未改变；已确认的刀具指定和字段不可重放。每个剩余字段以新的有界读取决定是否写入，避免前一 setter 改变别名后使用过时的跳过判断。

标量读取复用 `sw_cam_guide_field_read_batch`，保留进程、文档、配置和证据检查。写入仍使用独立的强校验及持久化 pending 日志。只有全部13项绑定和4组参数通过最终读取后，才允许一次 Save；随后核对源文件摘要、参数和消息订阅清理。

2026 实例上已完成16个剩余字段的核对/配置与一次 Save：返回0、文件摘要改变、保存后完整读数一致、无 CAM 消息错误且订阅已断开。此结果没有生成新轨迹，也尚未证明重新打开后的 CAM 持久化。离线继续协议/MCP包装45项、批量字段读取20项通过；重新打开及制造资格仍是独立检查。

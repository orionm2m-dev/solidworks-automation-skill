# Read-only qualification of the recovered pocket pair

`solidworks_cam_qualify_recovered_pocket_read` performs one complete read-only comparison against a genuine completed RecoveryV2 Save/CL receipt. It cannot accept the running recovery, the earlier uncertain GTP receipt, or a successful-producer receipt relabelled as recovery. The file-only recovered-context adapter proves the original single generation, explicitly observed XYFeed delta, unchanged protected operation, actual integer-zero Save/source transition and actual exported CL bytes/count. It preserves the uncertain original and all historical pins. The old target hash is replaced only by the proven Save transition.

The caller explicitly supplies the owned process lifetime, saved target/source hash, feature ID, ordered Rough/Contour IDs, recovered receipt path/SHA and a fresh output receipt path. The server resolves the already registered CAM add-in only after file-only preparation. The runtime implementation inherits only the existing read-only Context identity/message lifecycle; it does not inherit a tool mutation backend.

The capture sequence is fast full definition -> retained complete parameter payload -> fast full definition. Each full definition includes CAD/body/raw-tree/circle checks before and after its retained CAM inventory/header reads. The parameter reader and getter payload remain unchanged. Both observed inventories and every parameter must equal the admitted saved snapshot. The generated mapping is taken from genuine authority, never added to an attempted-generation list.

All admitted rich pins remain exact. New reader/dependency/ABI pins are added through the bounded canonical 128-pin union, without replacing historical hashes. The final check repeats admitted file and raw CL byte verification after clean message disconnection and exact owned document/source validation. Partial parameter observations and phase timings are durably retained; any observation, event, cleanup, source, identity or runtime failure clears every acceptance flag. The outer MCP wrapper also revokes the receipt if runtime identity changes after return.

There is no Save, GTP, setter, tool assignment, export, document activation, native retry or once marker. Repeating a read requires a new output receipt; it never authorizes a mutation. Output flags explicitly deny production/tool/cutting/unit qualification and reuse as mutation authority.

Timing fields separate before_definition, retained_parameters and after_definition. Definition diagnostics separately report before_cad, bootstrap, inventory_and_header and after_cad. The scheduling contract is non-atomic and excludes no transient external A-to-B-to-A changes; retained getters do not perform global ActiveDoc/file-metadata checks on every call. No write lease or performance improvement is claimed before a genuine native comparison. This is one current-context observation, not universal native parity.

The package includes the separately frozen retained reader and fast/prebound definition dependencies and their portable tests. File-only admission tests, read-only lifecycle/MCP tests and a joint import/parity run are separate evidence from later native qualification. Runtime installation and the single native probe remain externally owned and occur only after the active recovery terminates.

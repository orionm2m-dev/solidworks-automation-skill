# Current saved MILL process export

`solidworks_cam_export_process_data` exports one complete active MILL process to a new local `.prtcam` file through `ICWApp4.ExportCAMData` (DISP59). It does not import data, rebuild CAM, calculate toolpaths, save a model, or call a TechDB setter. The whole process is exported; the requested operation list is a protection scope, not an export selection.

The input pins the owned PID and lifetime, exact saved part path/SHA, a three-step feature and its two setup IDs, the complete ordered operation IDs, generated-operation count and record total. The existing `sw_cam_mill_current_compound_read._capture` reads the full bounded operation inventory and target profile before and after. Thus this route also accepts a later saved revision with more generated paths when the caller supplies the actual new hash and counts. It does not consume a stale completed-configuration receipt as authority. Up to four immutable JSON receipts may be supplied as provenance only; their contents and history are not rewritten.

The context reuses the existing process-lifetime check, operation lock, `CamMessageSession`, typed getters and `ScopedCamDispatchGuard`. Dispatch is a callable `invoke` with keyword `persist_pending`, not a method-name argument. Before the callback, the guard repeats source/evidence hashes, active document, process and event checks after the durable pending marker. The native HRESULT is written before any post-export read. Only strict integer zero is accepted. Failure after a claimed attempt is uncertain and never retried automatically, even with a different output filename.

The `.prtcam` must have a fresh exclusive local directory whose parent already exists. No output directory is created during validation. Native output must be the sole nonempty file in that directory, at most128MiB, with stable size and SHA through cleanup. Receipt and attempt-registry directories must already exist. Source and provenance may not alias the output. The attempt key is bound to the canonical source path and saved SHA.

Success means the native export returned zero, the bounded captured CAM state was unchanged, the saved source bytes stayed unchanged, event cleanup and runtime identity passed, and a stable archive file exists. It does not validate the opaque archive contents or restoration. Host `needs_save=false` is not a general independent CAM dirty-state proof. Hidden geometry, all machining parameters and CL coordinates are not covered by this inventory comparison. These limits are explicit result flags.

Official installed CAM help states that process export includes operations and associated parameters but excludes stock parameters. Importing into a similar part requires association/rebuild, which may update setups and regenerate modified toolpaths. Therefore an exported archive is not a completed CAM migration or manufacturing approval. No import/rebuild policy is part of this endpoint.

Software tests use the actual `ScopedCamDispatchGuard` with fake COM objects and real temporary files. They cover pending-state ordering, source drift immediately before callback, native exceptions, wrong return types/codes, missing/empty/additional output, changed captured state/source, CAM events, cleanup/runtime failure and replay rejection. Native export remains unqualified until separately executed on an owned test case.

Installation is not performed by this staging package. Install the module plus the two AST nodes in `server.fragment.py` only under an explicit runtime lease. Do not replace the entire installed server with a staged historical copy.

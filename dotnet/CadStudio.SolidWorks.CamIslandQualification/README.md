# Permanent CAM island qualification sidecar

This is a fixed native SOLIDWORKS add-in extension, staged for installation by the owning workflow. It does not replace, unload, register over, or shadow the existing AddInHost assembly. The command and metadata interface are permanent public contracts with stable GUIDs. The code uses the installed public SOLIDWORKS/CAM interop interfaces. No UI automation, macros, external feature-pointer marshaling, generic member invocation, or native REA is present.

`GetHostStatus` (DispId 1) returns host PID/lifetime, loaded assembly path/MVID, owner/current thread, STA state and dispatcher readiness. It does not call CAM. `QualifyCreatePocketAndIslands` (DispId 2) accepts the exact request fields in `Qualification.Fields`; there is no generic command selector. The first authorized native pilot uses `island_count_limit=1`. The implementation also validates the fixed sequence with `island_count_limit=4` for a separately authorized fresh copy. Values 2 or 3 are rejected. A successful first-island copy cannot later be continued by this command.

Before the first mutation, the command validates exact PID/lifetime, active path, SW/CAM configurations, loaded MVID, disk hashes, distinct source/copy file IDs, clean saved copy, setup64 and operationSetup65, empty CAM feature/operation inventory, exact feature-tree and body fingerprint, and the five named sketch counts/types/transforms. Body bounds are exact and mass arrays reuse relative tolerance 1e-10 without absolute tolerance. Native paths are exact normalized Windows paths; the caller must supply the same canonical spelling reported by SOLIDWORKS. Z: and UNC aliases are not silently conflated.

One durable marker per copy is exclusively created and flushed before the factory dispatch. Every factory/Add dispatch records pending before call and returned or exception after call. CreateMillFeature2 disables automatic islands. All AddIslandToFeature calls receive the exact same locally returned factory object on the owner STA. A failed or uncertain action is never replayed. No Save, GOP, GTP, AFR, rebuild, feature removal or mutation rollback is implemented. Exactly one document may be loaded: the qualification copy. The protected source remains a disk authority and cannot simultaneously be loaded.

After a returned Add, fresh feature lookups verify scalars and ordered profile names. Final indexed analytic chain reads are bounded to the declared outer profile and requested islands. Physical placement/depth, persistence and machining qualification remain false. After a native mutation exception, at most one separate fresh header/snapshot diagnostic is attempted; it cannot upgrade the uncertain result.

`NativeContractHarness.cs` uses a fake backend and synthetic file bytes. Its 241 checks cover logical document-context validation, rejected observation recording, and one/four additions, object retention, preflight errors, native exceptions, false returns, header failure, chain failure, durable receipt equality, persistent no-replay markers and cleanup/late-event failures. It never activates COM or opens CAD. Successful compilation, exported TLB metadata and these tests do not prove live SOLIDWORKS behavior.

Build inputs are explicit: `ReferenceDirectory`, `DotNet`, `Roslyn`, `TlbExp`, and release `SigningKeyPath`. The signed key establishes assembly identity, not an Authenticode publisher guarantee. Run `Build.ps1 -Test` using explicit tooling/reference paths; release build additionally requires the key. Output is only under this package's `bin`. TLB export is 64 bit and performs no registration.

Runtime ship files: `CamIslandQualification.cs`, `Build.ps1`, this reference, the two test sources (`tests/NativeContractHarness.cs`, `tests/CAD_BASELINE.json`), signed DLL/TLB, and the three exact referenced interop DLLs. Synthetic test-run directories and harness executable are evidence only. The owner handles fixed-GUID registration with exact backups/rollback and verifies actual native loading; this package does not claim HKCU registration alone establishes SOLIDWORKS discovery. No auto-start key is requested.

Only three hash-matched public reference identities are resolved. No CAS or machine security setting is changed. The old host is inspected by metadata only because its constructor writes diagnostics.

The constructor remains side-effect-free, and GetHostStatus's existing schema is unchanged. Unavailable diagnostic storage still prevents connection success; a failed ConnectToSW is never represented as connected. The installer/lifecycle owner must verify actual native status after controlled process replacement; an old loaded assembly must not be overwritten or assumed to reload from a new disk SHA.

Additional permanent test sources are `tests/ComProjectionHarness.cs` and `tests/Test-ComProjection.ps1`. `OWN_CCW_PROJECTION_FIXED_02.json` and `OFFLINE_TEST_RESULT_02.json` are the saved offline evidence. These tests make no ConnectToSW, CAD or CAM call and perform no registered COM activation.

# Source guard repair candidate

This candidate is based on revision 2 source SHA256 `40d0092598f9e49152dfe73ff8aa80a6df46762f57587856794520ad44ba4924`. It is a source-level repair proposal following a preflight-only native stop. The source-review step built only the offline harness EXE. The subsequent production build is recorded separately in NATIVE_COMPONENT_FREEZE_03.json; it performs no SOLIDWORKS connection or registration.

The original compound predicate cannot identify which operand failed. The expected part type remains 1, matching the public enum. The repair removes the undocumented assumption that repeated active-document calls return one reference-equal managed object. Reference equality is diagnostic telemetry only for document wrappers; it remains a required internal invariant for the exact locally created feature passed to AddIslandToFeature.

The replacement requires exactly one loaded SOLIDWORKS document, the exact qualification-copy path and configuration, process PID/lifetime, and a clean saved document during preflight. The protected source remains a disk authority and cannot simultaneously be loaded. Before and after CAM observations, the SW document boundary is checked. Each fresh and retained CAM document separately supplies its type/configuration, mill machine, one setup and operation setup, native IDs, setup axis/origin, expected feature membership (empty before Create, exactly the local created ID afterwards), and zero operations. Each document resolves the IDs of its own returned objects. The factory setup, retained document, and local feature object are never replaced.

This binding is stronger than matching IDs: it combines the public active-document contract, a unique loaded SW document, exact path/configuration/lifetime, two independently read CAM contexts, inventory/geometry metadata, existing file/fingerprint checks and quiet events. There is no public CAM document-path/native-document-ID getter in the inspected interfaces. It does not provide an independent cross-product identity proof beyond that public active-document contract. The two-identical-documents case is rejected rather than treated as a matching ID.

`boundary_observations` stores up to 64 bounded rows, including SW before/after, fresh/retained CAM scalar reads, reference-equality telemetry, and partial observation/exception detail. Completed scalar observations are flushed before validation; exceptions flush any partial context already read. Boundary reads do not repeat body or sketch geometry extraction. Full CAD/sketch verification remains in the existing preflight/capture path.

The request and GetHostStatus contracts, fixed GUIDs, command sequence, once marker, single local factory object, first pilot limit 1 / supported limit 4, no-retry behavior, and no Save/GOP/GTP/AFR rules remain unchanged. A source repair and passing offline tests do not prove the original failed operand or establish live native qualification. Root owns any later deployment decision.

The permanent C# harness adds positive 0/1-feature context fixtures and rejects two loaded documents, a wrong active/loaded path, process lifetime drift, dirty preflight, same setup IDs with wrong configuration, absent/wrong-type documents, changed axis/origin, changed feature ID/count, nonempty operations, setup ID/count drift and collection drift. Every rejection checks its distinct error and that the full observation was recorded before it was thrown. Existing mutation/no-replay tests remain.
